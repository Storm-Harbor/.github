# Security reporting

Do not disclose exploitable vulnerabilities, credentials, customer data or private knowledge in a public issue. Use **Security → Report a vulnerability** in the affected repository when private vulnerability reporting is enabled. If that option is unavailable, use a maintainer's existing private contact channel to arrange a confidential report; do not post the details publicly while seeking one.

Include the affected revision, a minimal synthetic reproduction, impact and suggested mitigation when available. Do not test against another organization's environment or production infrastructure without its explicit authorization.

The current release is documentation and safe simulations, not a supported production recovery engine. No production support SLA or supported stable runtime versions have been published. Maintainers coordinate validation, remediation and disclosure with the reporter according to the scope and impact.
