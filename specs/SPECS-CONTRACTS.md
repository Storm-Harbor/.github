# Contract ownership and architectural boundaries

Versioned contracts define meaning, ownership, invariants, state transitions, authorization scope, validation, errors and compatibility before a transport representation is selected. New executable implementations use Go 1.26.x.

Use explicit boundaries: transport model → inbound adapter/mapper → application command/query → domain → outbound port/adapter → persistence/provider representation. Presentation maps back through an allowlisted response contract. Never return raw persistence entities or import another service's source.

Shared cross-repository semantics have one versioned owner in a cohesive `storm-lib-*` module. Publish and validate producers before consumers adopt immutable versions. Provider-local DTOs remain explicit mapped representations. Pure mapping does not generate identities, infer permissions, access storage or perform network calls.

Go expected failures use typed transport-neutral errors with code, category, localization key, safe arguments and bounded details. Public HTTP APIs use explicit versioned OpenAPI and an agreed safe error representation; API design must reconcile existing RFC 9457 expectations rather than copying an incompatible envelope. Presentation localizes human text; business decisions use stable codes. Adapter boundaries normalize dependency and unknown failures.

Every resource, operation and retrieval has effective organization/project scope. Diagnostic correlation does not establish identity, authorization, replay resistance or idempotency. New request IDs are generated by the receiving boundary; external diagnostic values are bounded/sanitized. Idempotency binds authenticated scope, operation, contract version and canonical payload, with atomic persistence, bounded retention and conflict behavior.

Cloud-specific account structures remain in adapters. Multicloud recovery declares and verifies compatible source/target mappings. YAML/schema/resource and controller versions are frozen into each approved run. Custom kinds require admission, status, compatibility/conversion, controller isolation and tested lifecycle behavior. AI/RAG/CLI is optional and cannot bypass deterministic orchestration, permissions, approval or data policy.

Public projections, events, errors, evidence and metrics use allowlists. Never expose tokens, private keys, raw prompts/corpora or another project's data. Metrics avoid sensitive/high-cardinality labels. Runtime integrations define bounded timeout/cancellation, retry classification, backoff/jitter and circuit-breaker behavior where applicable; do not retry deterministic denial or an unsafe mutation.
